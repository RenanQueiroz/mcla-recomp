# The hand-off trace (2026-10-28)

What it is and how to read it: `patches/README.md`, `rexglue-handoff-trace.patch`; the options and the script in
`launcher/README.md` (Measurement tools, "The hand-off trace"). This note holds what was measured with it.

## State when this was written

Nothing has been run. The patch, the hooks (`config/handoff_trace.toml`), `launcher/dev/handoff_trace.py` and the two pads
were written and checked as far as no game allows: the SDK builds in CI with the patch applied, the host sources compile
against it (stand-ins for the generated headers), `check_pins.py` passes, and the script reads a synthetic trace in the file
format (written independently of the C++ writer from the layout in the script's header). The hooks' addresses come from
the generated code (`sub_82148A10` entry, loop head `0x82148AA8`, exit `0x82148AE8`; `0x82161880` after the last store of
`sub_82161210`; `sub_82144888` entry; `0x82160144` after the store in `sub_82160088`; `0x82305E90` in `sub_82305E38`;
the entries of `sub_822C0980`, `sub_82305D00`, `sub_823057E8`, `sub_82131008`) and have not been through codegen yet.

## What the profile led to expect (from `profiling-2026-10-26.md`, before the pump wake on demand)

Free roam, 16 logical processors, D3D12, native, uncapped: 6.82 ms a frame; the update thread 6.46 ms of CPU, 2.8 of it in the
ring-slot wait; the render thread 3.83 ms; the render thread waiting for work 35% of the time while the update thread ran,
the update thread polling 27% while the render thread ran, both running 25%. With the pump wake on demand (v0.2.0) the frame
is 4.17 ms at 16 logical processors: about the render thread's CPU, so little is left to win there. At 4 logical processors the
default is the game's own 7 ms Sleep (the wake on demand failed the audio check there) and the CPU, not the hand-off, is
the limit.
