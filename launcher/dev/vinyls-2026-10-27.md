## What is known from reading

### A: vinyls

- The SDK has `readback_resolve` (`none`, `fast`, `some`, `full`; hot-reloadable) and the legacy `d3d12_readback_resolve` and
  `vulkan_readback_resolve`. It acts on every resolve (render target to texture memory): the destination is copied to a readback buffer and, for
  `full`, the command thread waits for the GPU and copies the result into guest memory at once; `fast` and `some` copy the previous frame's. At 3x
  the resolve first goes through a downscale compute pass to the 1x layout. So `full` costs a GPU wait per resolve, per frame.
- Xenia Canary's compatibility list (xenia-canary/game-compatibility #145, 545407F8) labels the game `gpu-readback` ("GPU-written data read
  on CPU (HDR adaptation, save images)") and `gpu-occlusion-query` (`occlusion_query = "fast"` "fixes unoccluded lens flares"). Vinyls are not
  named there, but the pattern is the one `readback_resolve` is for: a result the GPU makes (the vinyl layers drawn into a render target and
  resolved to a texture), which the game then reads with the CPU (to bake it into the car's texture), sees as stale memory when the emulation
  keeps it on the GPU, and so bakes an empty livery. The editor shows the layers because it draws them on the GPU every frame.
- The player's career save has no vinyls: `UserVinylData` in `mc4.sav` is a pool of 223 default entries
  (`00002fae2fae00000000ffffffff00000000ffff`), then 0xCD fill. A vinyl has to be made in the editor (garage, vinyl editor) to see the bug.
- Tools the tree has for finding the code that reads the texture: the dev pad (`launcher/dev/pad.py`, `src/dev_pad.cpp`: `screens` lists the UI
  manager's movies by name, `set`, `peek`, `dump`, `shot`), the render markers (`src/render_markers.cpp`: the game writes its frame and render
  phases into the command stream, `mcla_render_markers_all_phases`), the guest crash tracer (`src/crash_trace.cpp`: host address to guest
  function) and the sampling profiler (`mcla_profile`).

### B: taillights

- Defaults of the launcher (what a new player gets): Direct3D 12 ("Automatic"), native 720p, 30 FPS cap, 2x MSAA, frame generation off,
  motion blur on (the game's own setting, `mcla_motion_blur`), FSR sharpness 0.2.
- The night's light glows, coronas and beams (85 to 100 additive draws) are drawn after the tone map (phase 0x10000000,
  `frame-structure-2026-10-16.md`), in display space, together with 24 point draws without a target that are occlusion queries for the glows.
  The motion blur (`sub_8260E9A0`, post phase, 640x360) works from depth, the stencil vehicle ID and per-vehicle matrices, before the tone
  map; the pass runs in every 3D frame even with MOTION BLUR off (`rexglue-temporal-aa.patch`: it is the anti-aliasing point). So the setting
  does not remove everything that blurs, and the glows are not blurred at all.
- FSR 3.1 anti-aliasing runs over the scene texture before the motion blur with motion vectors made from the game's per-vehicle matrices;
  its trails are warned about in the launcher ("possible faint trails behind fast-moving things"). The glows are after it, so they
  can't be smeared by it. Frame generation interpolates the finished picture, glows included, without motion vectors for them.
- Occlusion queries are host queries (`occlusion_query_enable`, on by default; the fake count 1000 otherwise). With 2x MSAA and resolution
  scaling the sample counts are larger than on the console.

## What the patch does

`rexglue-resolve-readback-rules.patch` (`patches/README.md`): `readback_resolve_rules` reads back only the resolves a rule matches (address
range, length, destination pitch, height, format, source, render phase; mode `full` by default), whatever `readback_resolve` is, and
`resolve_log_frames` logs the resolves of the next N frames with those properties. Off (empty rules, `readback_resolve=none`) the resolve
code is the old one. The idea is the cheapest fix that needs no knowledge of the game's code: log the resolves in the vinyl editor and when
leaving it, find the one the CPU needs (by bisecting the rules), and ship that rule as a default for the title.

## How to find the rule (the runs)

1. Reach the vinyl editor with the dev pad (`launcher/dev/scripts/explore-pause.pad` shows how the pause menu is walked; the garage is a pause
   menu entry, `src/warp_fix.cpp`), make a vinyl, leave. Take `shot`s of the car in the garage and in free roam, with `--readback_resolve=none`
   and `full`.
2. In the editor and after leaving it: `set mcla_render_markers_all_phases true`, `set resolve_log_frames 3`. The log lists the resolves with
   their render phase; the vinyl bake is the one that is not in the usual frame (no phase of the usual list, an odd size, or only there).
3. `set readback_resolve_rules len=...,pitch=...,height=...,fmt=...` with the properties of the candidates, one at a time, then leave and
   look at the car again. A rule that restores the vinyls and costs nothing in free roam is the fix: it goes in as the title's default (a
   `REXCVAR` default set at start-up in the game, like the other PC defaults).
4. If the destination is a fixed address the rule can use `addr`; if it moves, `pitch`, `height`, `fmt` and `phase` should still tell it apart.
